- Superseded by: N/A
- Related: PR #137、`docs/design.md` §7.1

## コンテキストと変更契機

ADR-0099は常設操作を限定していたが、実装は64rem以上で速度と音量を常設していた。同じADR内にも常設音量への言及があり、設計と実装が一致していなかった。PR #137のレビュー対応で、利用者は「広い画面での常設を維持し、後継ADRで設計を更新する」を選択した。

## 決定

| 幅・状態 | 速度・音量の置き場 |
| --- | --- |
| 64rem以上・折りたたみ | 常設行。速度は選択、音量はアイコンからPopover |
| 40rem以上・展開 | 板の展開段。常設側は終了遷移が完了するまで外す |
| 40rem未満・展開 | Drawer |
| 64rem未満・折りたたみ | 題名・余白から展開すると操作できる |

幅による違いは近道の有無に限る。全幅で展開後に同じ機能へ到達できる。常設操作やそのportalが幅変更で消えるとき、そこにfocusがある場合だけ、残存する題名へ戻す。

終了遷移も表示期間に含め、同じ操作・失敗通知・参照先idを二重に出さない。Drawerから広幅へ移る場合はDrawerの終了を待って展開段を出す。待ち時間は固定タイマーで推測せず、Base UIが管理するDOMの寿命から判断する。閉じたDrawerのジェスチャーはEscape・幅変更を含め打ち切る。

## 判断要因

- 広幅では聴きながら速度・音量をすぐ調節できる。
- 狭幅では題名と再生操作の幅を確保する。
- 幅変更や連続操作でも、キーボードの現在地と操作対象を失わない。

## 却下案

| 案 | 却下理由 | 再検討条件 |
| --- | --- | --- |
| 全幅で速度・音量を展開後だけに置く | 広幅での近道を維持する利用者の選択に反する | 常設操作の利用が少なく、題名の可読性を優先するとき |
| CSSだけで常設操作を隠す | portalの候補やPopoverが取り残される | portalを使わない構成になったとき |
| 400ms後に常設操作を戻す | 再開閉すると古いタイマーが次の終了遷移を妨げる | N/A |

## 結果

- 広幅の近道と、全幅共通の展開後の操作を維持する。
- 幅によって近道の有無が変わるため、両方の到達経路とfocus移動を検証する必要がある。
- Drawerから展開段への切り替えには、終了アニメーション分の待ちがある。

## 再検討条件

- 常設操作が題名を圧迫する幅や文字サイズが見つかる。
- 操作の追加で常設行に収まらなくなる。
